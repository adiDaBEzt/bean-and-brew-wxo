# 2. Deploy the Orchestrate agents

Connect the ADK to an IBM Cloud watsonx Orchestrate instance, attach the five Snowflake service identities, and deploy the master agent and its two collaborators. Run the commands from the lab repository root in a dedicated lab instance. The connection and agent names are shared within the instance.

## Connect to your IBM Cloud instance

1. Launch watsonx Orchestrate from IBM Cloud. Open your profile menu, then **Settings → API details**.
2. Copy the **Service instance URL** to `WXO_URL` in `.env`. Keep the `/instances/…` part of the URL.
3. Use **Generate API key** to create an IBM Cloud IAM API key for the lab. Put it in `WXO_API_KEY` in `.env` so the backend can obtain an IAM access token. Keep it in `.env` and enter it only when the ADK prompts. [IBM Cloud ADK setup](https://ibm.github.io/EEL-agentic-ai-bootcamp/labs/environment-setup-lab/wxo-client-setup/)

```bash
instance_url="$(venv/bin/python -c 'from dotenv import dotenv_values; print(dotenv_values(".env")["WXO_URL"].rstrip("/"))')"
venv/bin/orchestrate env add --name bean-brew-lab --url "$instance_url" --type ibm_iam
venv/bin/orchestrate env activate bean-brew-lab
venv/bin/orchestrate env list
```

For later sessions, reactivate `bean-brew-lab` to refresh an expired token. **Checkpoint.** The ADK lists `bean-brew-lab` as active and shows your service instance URL.

## Check the model catalog

```bash
venv/bin/orchestrate models list --all --raw
```

The three lab agents use **Claude Sonnet 4.6 on Amazon Bedrock**, model ID `bedrock/us.anthropic.claude-sonnet-4-6`. Verify that the model appears in your tenant and is allowed. If it is unavailable, choose a supported model with tool calling from the same list, such as `groq/openai/gpt-oss-120b` when available, and use that model ID for the `llm` field in `bb_hr_agent.yaml`, `bb_finance_agent.yaml`, and `bb_master_agent.yaml` under `wxo/agents/`.

## Configure connections and import tools

Complete [Module 1](01-snowflake.md) first. Each connection uses the Snowflake account identifier, a dedicated service user, and the corresponding PKCS#8 private key generated by the bootstrap.

| Orchestrate connection | Snowflake service user | Private key |
| --- | --- | --- |
| `bb_sf_barista` | `BB_BARISTA_SVC` | `snowflake/keys/barista.p8` |
| `bb_sf_manager` | `BB_MANAGER_SVC` | `snowflake/keys/manager.p8` |
| `bb_sf_regional` | `BB_REGIONAL_SVC` | `snowflake/keys/regional.p8` |
| `bb_sf_finance` | `BB_FINANCE_SVC` | `snowflake/keys/finance.p8` |
| `bb_sf_hr` | `BB_HR_SVC` | `snowflake/keys/hr.p8` |

```bash
bash wxo/scripts/02_connections_tools.sh
venv/bin/orchestrate connections list
venv/bin/orchestrate tools list
```

The script checks the active instance and keys, provisions team key-value connections in **Draft** and **Live**, and imports the Python tools. It reads the private keys from disk and sends them to the configured Orchestrate instance over HTTPS. If a retry prompts you to update existing tools, confirm only the lab tool names.

**Checkpoint.** All five connections have credentials in both environments. The six tools begin with `bb_`, including `bb_get_inventory`, `bb_get_team_roster`, and `bb_get_salary_summary`.

## Import the collaborators, then the master agent

```bash
venv/bin/orchestrate agents import --safe --file wxo/agents/bb_hr_agent.yaml
venv/bin/orchestrate agents import --safe --file wxo/agents/bb_finance_agent.yaml
venv/bin/orchestrate agents import --safe --file wxo/agents/bb_master_agent.yaml

venv/bin/orchestrate agents deploy --name bb_hr_agent
venv/bin/orchestrate agents deploy --name bb_finance_agent
venv/bin/orchestrate agents deploy --name bb_master_agent

venv/bin/orchestrate agents list --kind native --verbose
```

The master definition references the two collaborators by name, so import them first. After the three successful deployments, find the object with `name` equal to `bb_master_agent` and copy its `id` into `WXO_MASTER_AGENT_ID` in `.env`. The backend uses the master agent ID for Runs API requests.

**Checkpoint.** The CLI reports successful Live deployments for all three agents, and `.env` has the master agent ID from this tenant.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| The ADK reports an expired token | Run `venv/bin/orchestrate env activate bean-brew-lab` and enter your IAM key. |
| The script reports the wrong environment | Compare the URL from `venv/bin/orchestrate env list` with `WXO_URL` in `.env`. |
| Tools report missing credentials | Check that the five connections have credentials in **Live** as well as **Draft**. Confirm the `private_key` belongs to the matching Snowflake user. |
| Deploy fails on a model error | Select a model allowed by the tenant and reimport the three updated YAML files before deploying again. |

## Clean up a dedicated lab workspace

If you are finished with the lab resources, undeploy and remove the lab master first, then its HR and finance collaborators, in Orchestrate. Remove the six lab tools before deleting their five `bb_sf_*` connections. Check that the workspace and resources belong to your lab before deleting them.
